# 基线档：改名单、重建、换档后未通过

名单格式在 `modlists.md`，存档命名与落点、第一次建档在 `onboarding.md`。本页是档建好之后的事

## 改名单就要重建档

经 `mods_from` 继承的上层清单改变，下层每份名单的档都要重建。带 `[rimrunner].save_from` 的名单借用被引名单的档，重建被引的那份。

## 建完之后必做

新档的头一轮回归比结论时**先分清哪些未通过是既有偶发**，两种情形手法不同：

- **同名单重建**（台账同一本）：`history` 的条带可以分辨——每条用例换档后首次执行时，引擎按基线档内容指纹插入一格换档标 `¦`，
  偶发表现为零星失败，换档带来的失败则从 `¦` 之后才开始连续失败；确认旧格作废再插入纪元标记
- **第一份新名单**（`passrate-<名单>.json` 是新的一本，没有旧格可看）：只能用旧名单那本的
  `history` 逐 Id 比对——旧本里本就零星失败者计为既有偶发，旧本满 `o` 而新本首轮失败者才是换档带来的失败

## 换档后未通过时先怀疑这一族

**建档执行的是真实开局流程，而真实开局里有一批事件安排在几百 tick 之后。**
建档在那之前存盘，产出的档即含**待触发**的事件：载入该档的实例在几个 tick 后触发这些事件，
而档本身没有任何可见异常。`build-save` 存盘后将档载入，空推 2500 tick；
其间进栈的阻断窗、新登记的 game condition、开始的研究类 job，出现任一项即建档失败并逐条点名。到点晚于这段的事件仍不会被检出

非被测产品的组件里随时间走的计数器、到点才赋值的字段，`build-save` 建档时量出来自动豁免。`[建档] 自动豁免` 行：首次填值的条目上终端，随时间变化的条目写入 RimRunner 日志。
批里每条推 tick 的用例都报同一个第三方组件的 `RESIDUE`，或有一条 `RESIDUE` 只说某个组件多出一个元素而原有元素未变，用当前的 RimRunner 构建重建档
