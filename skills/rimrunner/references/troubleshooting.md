# 执行不起来时

判一轮**已经执行完**的结果不在这里，在 `verdict.md`。本页是执行不出结果的那些形态，以及拍出的 mp4 没有声音或缺少声音

## `status` 的「游戏内：」附录

附录里的 `推进 tick N（X 前）` 与 `读数 <用例> 已产 K 段` 两行在读缓存快照时也是实时的：

- **判卡**（执行批次进行中观察 `status`）：至少隔一分钟再 `status` 一次，两次的 N 相同且 runState 仍 running 即为卡住。单次 X 大不构成卡住。PERF 一类用例的心跳只在每次量测末尾发出一次，一次可达几十秒，其间 N 不动、X 持续上升属正常

## `[内存] 排队：需 X GB（…），可用 Y GB，差 Z GB`

冷启动准入只有物理内存这一道闸：本实例的估值装不进可用内存。显存用到整卡减 `vramHeadroomMb` 之后，超出的部分记进需求，行里写成「显存溢出」。
可用 = 整机可用 − 别的实例尚未涨到估值的部分 − 预留。排到队首时，若停止那些别人已空闲满各自可停时限的实例就能装下，则从空闲最久的实例开始停止，足够即止。全部停止也不够时，一个都不停止，继续等待。
估值来源 `缺省估值，无实测` 取 4 GB。该名单该档位执行过一批后取最近几个实例的收尾私有字节最大值。
无实测时的估值用机器级 `config.toml` 的 `instanceMemMb` 调（0 = 不做内存准入，有实测也不采用），预留用同一份的 `memHeadroomMb` 调（缺省 2000），各键见 `onboarding.md` 的机器级配置表。`rimrunner machine` 第一行输出这份文件的路径

## 换 RimRunner 构建，批里却看不到效果

CLI 与引擎都取自 CLI 所在的 RimRunner 安装目录。
`rimrunner --version` 的「安装目录」行就是本轮在用的安装目录，同时输出版本与 commit。先核安装目录是否为预期的那个目录。
`RimRunnerHome` 只决定手动或 IDE 构建往哪个安装目录取引用（CLI 自行编译时取自身所在的安装目录）。测试 DLL 引用的 ref 与这个安装目录里的 ref 不匹配时，`run` 开始执行前以 `[拒绝/引擎引用]` 拒。把 `RimRunnerHome` 指向 `--version` 输出的那个安装目录，重新编译测试工程。

## 开始执行前被闸拒：按首行文案查

CLI 的拒绝行只陈述现场，可能的成因与处置收在这里。首行文案即索引。表中未列、按文案也无法处置的行，连同本次命令的 RimRunner 日志报给 RimRunner 的提供方。

| 首行 | 可能原因 | 处置 |
|---|---|---|
| `[WARN] mod 名单 … 上的项未装入进程：…` | 名单里列出、进程未装载；或那一行本身写错（行尾注释、两个 id 写在同一行，整行被当成一个 packageId）。没有用例声明依赖该项时批照常执行。有用例声明依赖该项时批次在开始执行前按 `[拒绝/包依赖]` 拒（退出码 5，零执行），行内点名依赖该项的用例类 | 写错的行改名单；其余按行内每项后的标注 |
| `[FAIL] 必需 mod 在名单里但未装入进程：…` | 描述符点名必需的包未装载进进程。实例载入后、开始执行前抛出，退出码 4，零执行 | 按行内每项后的标注；查 `Player.log` 里该包的加载错误 |
| `[WARN] Mods 目录里有 N 项无法读取 packageId：…` | Mods 目录里有目录无法读取 packageId：先查是否为别的 worktree 执行 `unmount` 后的残留。游戏跳过这些目录继续运行，批照常执行。名单上的项因此未装载时另有一行点名。每条路径后括注是否带合成标记、是否有登记认领 | 带合成标记的条目无需手动处理：无登记认领的条目由下一次冷启动清扫，被认领的条目由认领该目录的实例下次冷启动重建。无合成标记或标记无法读取的条目，确认其来源后再删除 |
| `[拒绝/产物不存在] <工程>：产物不存在` | 工程的 DLL 缺失：产物路径与工程实际输出不匹配，或编译完成后无产出 | 核对该工程的 `OutputPath` 与描述符里的产物路径；匹配后仍缺失，把这行与 RimRunner 日志里同工程的 `[产物闸]` 行报给引擎维护者 |
| `[WARN] 编译后仍有 N 个工程的产物早于下列文件，MSBuild 未重写`，下面逐行是 `<工程>：早于源文件 <文件>` 或 `<工程>：早于被引用的 <文件>`（几个工程因同一份文件陈旧时合成一行 `… —— N 个工程：…`） | CLI 刚按构建序编译过，DLL 仍比行尾的文件旧。照常执行，执行的是盘上现有的 DLL | 不影响结论。每轮都出现时，把这几行与 RimRunner 日志里同工程的 `[产物闸]` 行（DLL 路径与两侧时刻）报给引擎维护者 |
| `[WARN] 产物陈旧，未编译（描述符 autoBuild=false）：N 个工程`，下面逐行是工程与比它新的文件 | DLL 比那份文件旧，这一轮未编译、仍执行，执行的是 DLL 里的代码 | `autoBuild=false` 的产品自行编译列出的工程 |
| `[拒绝/冷启动锁] 实例 <名> 正由另一条命令执行前置闸或冷启动：<标签>（hh:mm:ss 起，Ns…）` | 别的命令正在这个实例上执行前置闸、判复用或载档；退出码 5。标签与机器锁票同形，末段是持锁命令正在执行的操作；括号里的「排队 Ns：…」说明持锁命令正排在准入队列里等待什么。`run`、`start` 遇到本树常驻自动实例的冷启动锁被持时不拒，改用临时自动实例（`[另起]` 行） | 本会话要执行的是 `build-save`、`showcase`、`film` 或 `--no-compat` 批 → 新建 worktree 并在其中执行（自动挂载）。行尾的 `；--force 撤销持锁的命令、停止该实例并冷启动` 写明加 `--force` 的后果（`live` 命令没有这个开关，行尾不写）；被撤销的命令输出 `[撤销]`，返回退出码 4 |
| `[拒绝/分片持有] 实例 <名> 正由分片组持有：<标签>（hh:mm:ss 起，Ns）` | 一条分片组正把这个实例借为一片（本树的自动实例被借片，或这个实例就是一条 `shard` 登记）。`build-save` 遇到该实例返回退出码 5，`run`、`start` 遇到本树常驻自动实例被借时不拒、改用临时自动实例（`[另起]` 行）；行尾的 `；--force 撤销该分片组并停止它正在执行的片` 写明加 `--force` 的后果 | 等这一组执行完（`status --all` 行末、`status` 实例行下输出该实例的持有者）。不需要那一组时加 `--force` 重新执行；本会话要执行 `build-save` 而不打断它，就新建 worktree 并在其中执行（自动挂载），或停止这一片再执行。`shard` 登记用 `stop --tree <树>/shardN --force`，借来的本树自动实例用零参 `stop --force`（本树的展台实例一并停止）。这一组记为未发片，余下的格由别的片认领 |
| `[拒绝/live 保留] 实例 <名> live 保留到 hh:mm:ss…` | 有会话刚用 `live` 驱动过这个自动实例：每条驱动命令执行完保留一段宽限（`liveGraceMinutes`，缺省 3 分钟），到点自动失效。保留期内 `build-save` 遇到该实例返回退出码 5，`stop`、`unmount` 遇到该实例即拒；`run`、`start` 不接手被保留的常驻自动实例、改用临时自动实例（`[另起]` 行），现场保留。行尾的 `；--force 停止该实例并冷启动` 写明加 `--force` 的后果：现场随之丢失，随后启动实例的那条命令冷启动 | 要执行 `build-save` 且本会话未驱动该实例 → 等保留到点，或新建 worktree 并在其中执行（自动挂载），不用 `--force` |
| `[机器锁] 等…（已等 Ns，排队上限 M 分钟）：…` | 机器锁排队：同时执行的实例已达上限（仅 `busyCap` 配为正数时）、P 核余量不足，或其他会话独占。该行下列出的票都是其他会话正在执行的命令，标签末段是该票在做什么（批次、建档、拍摄、展台等） | 上限不足时用 `--queue-minutes` 放宽（0 = 不设上限） |
| `[FAIL] P 核余量无法测量（…）` | `CpuHeadroom` 无法建立探针：无法读取 P 核 CPU 集、处理器组或系统处理器计数；`busyCap` 未配正数且 `busyReserve > 0`，CPU 准入无法执行 | 按本机核数配一个正的 `busyCap` 作硬上限，或写 `busyReserve = 0` 明确不做 CPU 准入 |
| `RimRunner 安装目录不完整：…` | CLI 只使用自身所在的安装目录，逐项列出缺少的部件：发布包解压不全或缺件，或调用的 CLI 不在安装目录里（从安装目录复制出来单独存放的 CLI） | 重新解压完整的发布包；调用安装目录下的 CLI |
| `[拒绝/实例忙] <实例类别> <名> 正在执行：runState=…` | 对方实例正在执行批次，退出码 5。`runState=saving` 是对方正在 `live save` 写盘，秒级即回 idle。`runState=driving` 是一条 live 驱动命令在执行，执行完实例通常仍被 live 保留。`run`、`start` 遇到本树常驻自动实例忙时不输出这一行，改用临时自动实例（`[另起]` 行） | `saving` → 隔几秒重新发送即可；本会话自己要执行 `build-save` 等 → 等对方执行完，或新建 worktree 并在其中执行；只为读对方结果 → 等待对方产出结果；确认卡死才 `--force` 抢占 |
| `[另起] 常驻自动实例 <名> <原因>，改用临时自动实例 <树>/spare<序号>` | 不是错误：常驻自动实例此刻不能接手（原因写在行内：冷启动锁被持、被分片组持有、被 live 保留、正在执行），这条命令在临时自动实例上照常执行。临时自动实例空闲满时限后自行停止、登记收回。本树此时有不止一个自动实例，落定实例那一行（`[冷启动]`、`[复用]` 或 `start` 的 `LOAD ONLY`）行尾含 `后续点名：--run-id <runId>` | 之后对这个实例的 `live` 带 `--run-id <runId>`，停止它用 `stop --run-id <runId>`（零参 `stop` 停止本树全部实例）；`run` 的结果按 runId 判（`judge <runId>`），`reports/latest.json` 可能属同树另一批 |
| `[FAIL] 本树有 N 个自动实例，用 --run-id 指定其中一个：`，下面逐行是 `--run-id <runId>  <实例名>`，冷启动中、runId 尚未上报的写作 `<实例名>（当前 runId 未知）` | 本树有几个自动实例同时在运行，不带 `--run-id` 的 `live --tree <树>/batch`、`stop --tree <树>/batch` 无法确定是哪一个，零执行，退出码 4 | 用本会话那条命令落定实例那一行里的 runId 重新发送；不认得列出的任何一个，就不是本会话的实例 |
| `[FAIL] 本树有 N 个运行中的实例，指定其中一个：`，下面逐行是自动实例的 `--run-id <runId>  <实例名>` 与别的用途的 `--tree <实例名>  <用途>`；只有一个临时自动实例在运行时写作 `[FAIL] 本树运行中的只有一个临时自动实例，用 --run-id 指定它：`；无运行中的实例时只有一行 `[FAIL] 本树此刻无运行中的实例` | 不带 `--tree` 或 `--tree` 不带用途段的 `live` 按本树运行中的实例找目标，已停的登记不参与也不列：只有一个在运行且不是临时自动实例时直接驱动它，否则零执行，退出码 4 | 照候选行的写法重新发送，自动实例用本会话那条命令落定实例那一行里的 runId；不认得列出的任何一个，就不是本会话的实例。无运行中的实例时先用 `start`、`showcase` 等启动 |
| `[FAIL] 本树没有当前 runId 为 <runId> 的自动实例`，下面逐行是各自动实例此刻的 `--run-id <runId>  <实例名>`；本树无运行中的自动实例时只有一行 `本树此刻无运行中的自动实例` | 给的 runId 不是任何运行中的自动实例的当前 runId：实例已被另一条 `run` / `start` 接手、已停止，或还在冷启动、runId 未上报（候选行写作「当前 runId 未知」）。零执行，退出码 4 | 候选里有本会话刚发的命令 → 用它的 runId；实例已被接手 → 旧 runId 不再指它，接手它的命令正在用它，不要驱动 |
| `[WARN] 基线档 … 的存档头与 mod 名单 … 不匹配` | 存档未按名单当前的清单构建：名单改过（含经 `mods_from` 继承的上层）、档建于别的名单，或测试 mod 改过前缀。批照常执行 | `run --save` 的批不输出这条，改为 `[指定存档]` 一行。差异只有旧测试 mod 一类时可忽略。有内容 mod 时按行内文案 `build-save --modlist <名单>`（指定另一份档后用例可能未通过，判别方法见 `saves.md`「换档后未通过时先怀疑这一族」） |

## 拍出来的 mp4 没有声音或缺少声音

mp4 片段带音轨，gif 与静帧不带音轨。带 `--mute` 时 mp4 也不带音轨。其余情形终端按镜头输出一行或几行，拍摄产物仍产出，仅音轨不全。拍摄目录 `film-run.json` 里该镜头那条记录的 `audio` 与该镜头的终端行对应：`voices`、`clips`；无声时另有 `silent`（「mp4 不带音轨：」后面的原因），无法读取的 clip 在 `unreadable`，未重放的行名在 `unknownRows`。

| 终端行 | 可能原因 | 处置 |
|---|---|---|
| `[film] <场面Id>/<镜头名> 音轨：0 次播放 · 0 个 clip` | 片段里没有播过声音；或播过的 clip 全部无法读取 PCM，此时同一镜头上方另有 `音轨缺一个 clip` | 没有 `音轨缺一个 clip` 警告时，让发声的动作落在片段里；有该警告时，按该行处置 |
| `[WARN] <场面Id>/<镜头名> mp4 不带音轨：引擎未写出事件表（…）` | 引擎在镜头结束时未写出音轨原料 | 看 RimRunner 日志 `引` 道里同一镜头的错误行，连同这一行报给引擎维护者 |
| `[WARN] <场面Id>/<镜头名> mp4 不带音轨：拍摄实例的时间未钉住：…` 或 `无法读取事件表：…` | 引擎与 CLI 之间的音轨原料有误 | 把行原文报给引擎维护者 |
| `[WARN] <场面Id>/<镜头名> mp4 不带音轨：ffmpeg 合成退出码 N …` 或 `合成失败：…` | 混出 wav 后合入 mp4 的这一步失败：退出码那一行行尾附 ffmpeg 的报错，`合成失败` 那一行是 ffmpeg 未能启动或文件读写出错 | 按 ffmpeg 的报错处理 |
| `[WARN] <场面Id>/<镜头名> 音轨缺一个 clip：<路径>：<原因>` | 无法读取该 clip 的 PCM，用到该 clip 的声音不进音轨，其余仍混入 | 把行原文报给引擎维护者 |
| `[WARN] <场面Id>/<镜头名> 音轨未重放事件表里的这些行：…` | 引擎记下一种混音器无法识别的行名，该行名对应的效果不在音轨里，其余仍混入 | 把行原文报给引擎维护者 |

`--keep-frames` 时音轨原料（事件表、PCM、混出的 wav）留在拍摄目录的 `<镜头名>.audio/`（`--roll` 时为 `<镜头名>.<种子>.audio/`）。报告时一并附上这些音轨原料。
