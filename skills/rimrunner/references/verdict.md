# 判一轮执行完的结果

命令面与开关在 `rimrunner <命令> --help`。本页是结果已经产出之后怎么下结论

## 结论行与退出码

结论行以 `[结果]` 开头，以 ` · 名单 <名单名|无>` 收尾。全部通过是 `[结果] ALL PASS —— N 项`，N 只计回归用例。另有窗外错误级日志、日志封顶这类附注时是 `[结果] ALL PASS（回归用例）—— 通过 N 项；另有 …`。本轮选读数用例时，在 ` · 名单` 之前追加 ` · 完成 M 项`。
回归档零执行、读数用例全部完成的是 `[结果] ALL DONE —— M 项（…）`

`run` 与 `judge` 的退出码同源，按报告的条目分档。分片组的报告只在组目录，不写入 `latest.json`。事后复看用 `judge <组目录>`，组目录即 `run` 收口输出的组清单所在目录，得出与收口同一份组视图（各片报告的校验由 `judge` 现做：编排进程侧的产出未写入只在收口时可见，归档在收口之后被删除或损坏的片落成 `报告无效`）：

| 码 | 报告里是什么 |
|---|---|
| 0 | 待处理项为零 |
| 1 | 有待处理项（`FAIL`、`UNCLAIMED_FAULT`、`SENTINEL_FAULT`、`NO_ASSERTIONS`、`INCOMPLETE` 之一），或有用例被拒（该条未执行，其余照常执行），或分片组里部分片被批次拒绝（待处理项写作 `<片标签>:REJECTED`，如 `shard2:REJECTED`；其余片照常执行，其中有更重的一档时取那一档；全部片的报告都是批次拒绝时才取退出码 5；片退出码 5 而报告无法读取时，按 `报告无效`（归档已删除或损坏）或 `无报告` 记，在 4 档），或报告里用例结果为零 |
| 2 | 用法错误（如传入未知开关或 `--case` 用法不合，未完成裁决） |
| 4 | 未完成：流程错误、超时、前置条件不满足而中途停止。报告在手但产出未写入磁盘也在这一档（结论行的待处理项里列 `产出未写入磁盘`）。分片组结论行的待处理项里有 `分片组:未认领×N`、`分片组:已认领未完成×N`，也在这一档；片无报告、报告无效、产出未写入磁盘、备片失败或未过一致性闸时，待处理项里以片标签开头的那一项（如 `shard2:无报告`）同样在这一档 |
| 5 | `REJECTED`：批次在开始执行前被拒，零执行。本树的自动实例被分片组持有或被 live 保留、命令因此拒绝接手的，也在这一档，同样零执行 |
| 69 | 游戏不可用：游戏可执行文件不存在、无法启动，或进程在引擎连上管道前退出（仅在直接观测到上述触发时取本档；Steam 未运行仅作诊断提示，不直接归入本档） |
| 70 | `ENGINE_FAULT`（含用例窗外的）或未捕获异常：本轮结论作废，见「引擎故障」 |

几种同时成立时取最大（70 > 69 > 5 > 4 > 2 > 1 > 0）。分片组结论行里片上不归用例的项冠片标签，按单批的同一项分档：`shard1:ENGINE_FAULT:窗外×1` 属 70 档，`shard1:SENTINEL_FAULT:窗外×1`、`shard1:指定输入件未读到:…`、`shard1:没有任何用例结果` 属 1 档。`<片标签>:退出码 N` 表示该片的退出码 N 在报告里没有对应的条目；成因见 `run` 收口时的 RimRunner 日志 [<片标签>] 行（`judge` 读组目录，不指各片日志）。

## 输出的上限

上屏的行每行正文至多 400 字符，超出的部分写成 `…（全文见 RimRunner 日志）`。JSON 输出不截断。

待处理超过 12 条时不逐条输出明细，改为输出 `[待处理摘要] N 条，全列见 RimRunner 日志`，其下按状态与成因归并成组，至多 20 组；每组列出条数与用例 Id，Id 至多 12 个，其余写成 `其余 N 条`。逐条明细（断言、哨兵、读数）只记；看单条用 `judge [<报告路径或组目录>] --case <用例Id>`；组目录下，该用例在各片的记录并成一条，状态、`errorSummary` 与读数取最严重的一片，指纹、哨兵、断言、引擎故障与诊断取各片之并，有片的报告无法读取时按待处理退出；全部片的报告都是批次拒绝时输出 `[拒绝] 各片 批次拒绝：…`；这一条为用例拒绝时列出 `[用例拒绝/…]`；组上另有不归用例的待处理项（如 `shard2:REJECTED`、`分片组:未认领×N`）时列成一行 `[FAIL] 分片组另有待处理：…`；都按待处理退出（不带 `--case` 的组视图在全部片的报告都是批次拒绝时取退出码 5）。状态与成因都相同的条目并成一组，组内各条的根因可能不同；成因只列每条最先列出的那一句，同条的其余成因只在明细里。

结论行超长时，待处理名单少列几项并写出 `其余 N 项`，拒绝描述与附注写成 `…（全文见 RimRunner 日志）`，都以 ` · 名单 <名单名|无>` 收尾。

## 启动错误级日志拒绝

只有确认属本产品或引擎的启动错误级日志才拒批：正文或栈里含本产品或引擎的程序集名，或正文点名本产品的 def、本产品 mod 目录下的文件。
栈上指名他 mod 的条目归入 `[ERROR]` 组的 `他 mod 启动错误级日志`，其余无法识别来源的条目归入 `来源未定的启动错误级日志`，都不拒批、仍执行。
`来源未定的启动错误级日志` 不拒批，须逐条读：正文只带引用目标的名字时，确定该目标是否属于本产品，属于则按本产品的启动错误级日志处理。

启动错误级日志拒绝的拒因下面，紧跟 `[许可未命中] 名单：启动错误级日志 "<子串>" · <理由>`。这一行是名单里声明、本轮认领到零条的许可。对着拒因正文核：
拒因正文里有那条错误级日志而未认领到，是子串写错，改子串。
拒因正文里没有那条错误级日志，是它这一轮未出现。许可本身成立，要看的是拒因里其余的错误级日志。

## 引擎故障

`[ENGINE_FAULT] <Id>` 与 `[ENGINE_FAULT/窗外] <位置>（当时用例 X）` 表示引擎未完成应做的事，退出码 70。
这一轮的结论作废，其余条目的通过与未通过都不作数。
`[ENGINE_FAULT/窗外]` 那几条里，正文以 `[契约闸]` 或 `[引用探针]` 起头的条目表示那一类检查这一轮未执行。
正文只输出首行，全文在报告 `engineFaults`（条目里与顶层）。启动期的引擎故障不输出 `[ENGINE_FAULT]` 与 `[ENGINE_FAULT/窗外]` 这两种行，落成批次拒绝（`[拒绝/引擎故障]`，退出码 5）

## 结论行之外的各段

终端只输出结论与当场需处置的内容。供事后回查的内容只记入 RimRunner 日志。收尾那行是 `RimRunner 日志：<路径>`。日志每行带 `屏`、`记`、`引` 三档道标之一，`引` 是本命令期间实例推来的引擎日志条目。分片组里各片的行在道标之后带片标签 `[shardN]`（借来的自动实例当片时为实例名，如 `[<树>/batch]`）：片的呈现是 `记`（片不上屏，各片的完整呈现只在日志里），该片实例推来的引擎日志是 `引`；`屏` 道只有组一级的行与组视图那一份。
分片组的组视图只有 `[分片组]` 事实行、片一级与用例一级的问题、组收尾折格失败的 `[台账故障]` 行（在三组之外，计入结论行附注）、`[ERROR]` / `[WARN]` / `[本轮范围]` 三组、产出清单与结论行；单批终端上的其余行（`[并行落点替补]`、`[偶发诊断]`、`[本轮首次未通过]`、引擎侧的 `[用时]` 等）只在各片的日志行里。三组里各片逐字相同的块并成一块，块首标出处（`各片：` 或 `shard1、shard3：`），块里的计数是每片各自的值，不累加；结论行附注同样不累加，句尾括注出处。多片时产出清单每份前缀片标签，份数是各片之和。
结论保持不变的发现按严重度收成两组。组头一行是 `[ERROR] 段名 · 段名` 或 `[WARN] 段名 · 段名`，各段的行缩进在组头下。
这些行在 RimRunner 日志里也每行带组前缀。`[ERROR]` 组是错误（批外用例问题、台账故障、载档错误级日志、
窗外错误级日志、他 mod 错误级日志、来源未定的启动错误级日志）。`[WARN]` 组是其余结论保持不变的发现。
`[WARN]` 组之后的 `[本轮范围]` 组只记范围，不是发现。该组列出这一轮声明跳过执行、改用哪份存档或改执行方式的用例与开关：`本轮排除`、`本轮缺席`、`兼容关闭`、`指定存档`、`指定输入件`、`溯源档`、`实验开关`。读结论时对着 `[本轮范围]` 看「全通过」覆盖的范围。
以下内容只记入 RimRunner 日志、终端不输出：`[汇总]` 计数行、`[预期错误级日志·新]`、`[许可认领]` 与 `[许可未命中]`（例外见「启动错误级日志拒绝」）、
`[名单认领的启动错误级日志]`、已认领警告的计数、`[名单] … · 台账 …`（未入账时改入 `[WARN]` 组）、`[能力]`、`[借读]`、`[输入]`（借读来的输入件）、`[用时]` 的引擎明细、
`[本轮排除]` 的条数与理由、`[本轮缺席]` 的类型全名

**要缩短用时，先读 RimRunner 日志里 `[用时]` 的引擎明细**：`[用时] 引擎 …（用例 … · 载档×N … · 存档 … · 契约扫描 …） · 端到端 …`，
先看墙钟落在哪一段，再改那一段。载档×N 是批内续段的整档载入（屏障批的 checkpoint、用例出错或主图无法还原时回基线）。存档是屏障存盘那一次，
用例那一段是用例体连同逐条的清扫、装配与还原。端到端是从 CLI 接到命令到本轮结束的墙钟（含前置闸、冷启动与进档等待），与引擎侧计时起点不同

段头自带说明。下表只写终端上没有的处理判据。行内未列退出码的段都不改结论与退出码：

| 段 | 判据 |
| --- | --- |
| 带键警告下的 `[新] <用例 Id>：<正文首行>` | 键行只列有这个键的用例，正文不输出；挂在键行下的 `[新]` 行是首次出现的那几条：这条用例上一次执行完的那一轮里未出现过这个键，下面列它本轮在这个键下的正文。比对的只是键，不比对正文：一条用例已挂有这个键时，同键下多出另一种内容不标新。批级的主体写「窗外」。键行里有、下面未挂 `[新]` 的行属复现，正文在报告 `warnings`。每个键至多列 3 条，其余条数写在行里，全文连同键名记进 RimRunner 日志（`[带键警告] [新] [<键>] …`）。段里出现「无跨轮基线，未分首次出现与复现」时这一轮不标新 |
| `[RESIDUE]`、`[STRAY-WINDOW]`、`[STORYTELLER-RESIDUE]`（`[WARN]` 组） | 正文在报告 `warnings`（用例条目里与顶层）。「本用例新增的 pawn」「自建物品」「建筑」行：用例生成的 pawn 用 `ctx.TrackPawn` 收，物与建筑用 `ctx.TrackThing` 或 `Defer` 收；跨 phase 要留的交棒（`contract.md` §7.0），行尾「ThingID 写进 checkpoint 状态但未登记交棒」的也改走交棒。独立小图归还时报的图面差（建筑、区域、指派、屋顶）在 `Defer` 里还原。「基线时休眠、本用例期间醒来的 pawn」行在主图上时：环境清扫已清除基线档的休眠 pawn，查产品场景装配是否放下休眠 pawn。「整局组件 / 世界组件 X 的存档状态…；写入方不是被测产品，不回档」行是 vanilla 或他 mod 的全局状态被用例触动（如建造收容平台置起的单向旗标）。这类状态无通用回写，其后用例的起点带有该状态。有用例因此未通过时，查这一行的引发用例能否改走不触动该状态的路径。同一个他 mod 组件在每条推 tick 的用例上都报，属随时间走的计数器，用当前的 RimRunner 构建重建档即自动豁免（`saves.md`）。落在哪条用例随批序而变，属到某个游戏年龄才写一次的状态，用名单的 `[rimrunner].component_exemption`（`modlists.md`）。「栈上窗口 X tick N 进栈，未推 tick 时由 <方法> 推入」与「栈上窗口 X tick N 进栈，推 tick 期间由 <方法> 推入」两行，是用例收尾后仍未关闭的窗。阻断窗（`forcePause` 或 `absorbInput`）已由引擎关闭，行尾写明，其后的用例不再受它阻挡。未推 tick 时由用例代码推入的窗口，将关窗操作移入 `Defer`。推 tick 期间推入的窗口，按推入方判断：推入方是到点的世界事件（用例未开过这类窗）时，查基线档里待触发的事件（`saves.md` 的「换档后未通过时先怀疑这一族」）。`STORYTELLER-RESIDUE` 是用例之间入队、被引擎清出队列的叙事者事件，正文写入队方 |
| `[本轮排除]` | 这些用例这一轮未执行，台账里无这一格。既有史据仍在，`history <Id>` 仍可查。`不适用` 之后列的用例由用例自报本环境无对象（`NotApplicableReason`），因而未执行，理由在 RimRunner 日志的同名行与报告 `inapplicableCases`。本该适用的名单下出现在这里，先查名单与基线档（缺 DLC、建档派系配错），成因在用例之外。命令里指定的用例不进这里：指定的用例不适用时记成该条的拒绝 |
| `[按组跳过]` | 按组选批（`run --group` 或名单 `[rimrunner].groups`）时，不带所列组的产品用例本轮未执行、台账里无这一格，终端只输出条数与组，Id 全集在 RimRunner 日志的同名行与报告 `groupSkippedCases`。条数与平时相差较大，先查名单的 `[rimrunner].groups` 与用例的 `[RimRunnerGroup]`；不按组过滤写 `--group all` |
| `[本轮缺席]` | 用例类（或该用例类的基类）挂 `[RimRunnerRequiresPackage]`，而本轮名单未列那个包、进程也未装载那个包时，整类不实例化，因而无 Id。终端按包计条数，类型全名在 RimRunner 日志的同名行与报告 `absentCases`。要执行这些用例，指定一份带那个包的名单 |
| `[指定输入件]` | 结论行点名读它的用例。这几条的通过与否按 `run --input` 指定的正文得出，与按盘上那份执行的同一用例不可比，台账照记。行尾「用例窗外」只在枚举分片格这类用例窗外读到 |
| `[输入件]`（`[ERROR]` 组） | 退出码 1。`--input` 指定的路径本批无用例读取：路径与用例读取的路径不匹配（相对数据根、区分大小写），或用例把读到的正文缓存在静态字段里、跨批沿用。路径不匹配时改 `--input` 的路径，用例缓存正文时改用例每批重读 |
| `[并行落点替补]` | 列出的用例这一轮的小图落在替补层上（主地表上找不到能立小图的地块时引擎改用的一层）。这几条未通过时先对照 `rimrunner-authoring` 的 `contract.md`「小图落在替补层上时」 |
| `[预期错误级日志·新]` 与 `[本次降级·新]` | 断言窗口（`AssertLogsError` 或 `AssertLogsWarning`）认领到的错误级日志或警告级日志，与用例经 `ctx.AddDegradedNote` 写出的降级说明，**只输出本名单下首次出现的那一条**。复现的条目不输出，条数在 `[汇总]`，全文在报告 `expectedLogs` 与 `degradedNotes`。`[预期错误级日志·新]` 只记进 RimRunner 日志，`[本次降级·新]` 在 `[WARN]` 组。预期错误级日志里出现一行未预期的正文，即说明认领子串写宽；该行属被测侧新增的错误级日志，应收窄子串。比对时正文里的连续数字、本轮生成过的 pawn 的名字各折成占位，只差实例编号、tick、计数、随机 pawn 名的计为复现。栈文本逐字比对，`[Ref]` 是栈文本的哈希，重新编译后栈逐字相同的也计为复现。每轮都出现同一类行、只差其余随机内容（不经 `PawnGenerator` 来的名字、随机 Def 抽样），说明产生该行的用例未钉住那份内容。段名不带「·新」是无跨轮基线（名单名非法），那时输出全文 |
| `[许可认领]` 与 `[许可未命中]` | 用例 `[RimRunnerAcknowledgeLog]` 许可的错误级日志或警告级日志，只记进 RimRunner 日志。两段每行都带许可的理由。`[许可认领]` 是本轮命中的许可，下面缩进列出被该许可认领的正文（同文只列一次，条数在「命中 N」）。`[许可未命中]` 是本轮零命中的许可，单轮零命中不改结论；用例的许可行尾带「连续未命中 N 轮 / Tolerance T」，本轮声明够不到的带「本轮够不到：理由」。连续未命中超过 Tolerance 另出 `ACK-NO-HIT` 警告（处置见 `rimrunner-authoring` 的 `contract.md`「登记期核对」）；分片组按组判，由组视图并进 `[WARN]` 组的带键警告段，各片报告的 `warnings` 里没有这一条，正文只在本次命令的 RimRunner 日志里（`[带键警告] [ACK-NO-HIT] <用例 Id>：…`），也不标 `[新]`。已发的片中有片未形成报告或报告无效时，组不判；用例在某片未执行到尾或有引擎故障时，组不判这条用例的认领。某片声明这条认领本轮够不到时，这条认领在该片不计，其余片仍判；被批次拒绝的片有报告，不计为缺。`[RimRunnerAcknowledge]` 键认领，以及名单 `[rimrunner].acknowledge`、`[rimrunner].acknowledge_startup_error`、`[rimrunner].known_failing` 零命中的，也列在 `[许可未命中]`（行里写「键 …」「启动错误级日志 …」「已知失败体检 …」）。认领的正文里出现未预期的一行，即说明许可子串写宽；该行属被测侧新增的日志，应收窄子串。有跨轮基线时，这条许可在本名单下首次认领到的正文行首标 `[新]`，复现的条目仍列出、不标（比对口径同 `[预期错误级日志·新]`）；无基线时不标。一条许可此前认领过正文、本轮又认领到一种此前未认领的正文，另出 `ACK-BROAD` 警告列出那些正文：单轮里无从得知的写宽看这一条。许可认领到的头一种正文只标 `[新]`，不出警告。改子串或栈锚的许可重新入账。同一格本轮认领到的正文归一数字与本轮生成的 pawn 名后不止一种、子串整串只是异常类型名，也出 `ACK-BROAD` |
| `[窗外错误级日志]` | 启动快照之后、任何窗都未开时的错误级日志（用例收窗后晚一帧的异步回调或协程异常，以及批与批之间；启动期的归启动错误级日志拒绝）。结论行带附注。批尾报告常与最后一个窗同帧写出，收窗后晚一帧的错误级日志出现在**同一实例的下一份**报告里。同一行每轮都在，即该行是某条用例的遗留或他 mod 的常驻噪声：或修源头，或把触发该行的用例改成在窗内等到它（在窗内由那条用例的 `AssertLogsError` 或错误级日志许可认领）。标签带「开始执行前的环境清扫」段名的行，来源是引擎在两窗之间清图，不是上一条用例的回调：被清对象的组件，或订阅该对象的 mod，输出该行。标签里「清 <ThingID>（入场 tick N 于<窗>←<来源>）」点名被清的那一个，按入场窗与来源去找把它带上图的用例或事件。无入场标时只写 ThingID（基线档原有的、载档前落图的，以及火、建筑这类不打标的对象） |

失败条目里缩进的内联标记：

| 标记 | 处理 |
| --- | --- |
| `调用栈 N 块见报告 newErrors` | 每块是 `Log.Error` 的调用点。异常的抛出点在 `errorSummary` 自带的栈里，抛出点与 `errorSummary` 的栈常不在一处。正文中的异常在输出该日志的线程上抛出，块尾另附 `异常抛出栈 ←` 一段。这一列与 `newErrors` 不同序，也不等长，按块首回带的错误级日志首段配对。按下标配会错位，且错位本身无标记 |
| 缩进的指纹行（报告字段 `failureFingerprints`；多行的终端只输出首行，全文见报告） | 残留指纹与伤害传播类指纹之外，FAIL 时还会现场计算这些读数。「<nick>：pawn 未归一化」：引擎 helper 生成后未过 `NormalizeForDeterminism`，随机 trait、年龄、装备进入 stat。`RimRunnerRaid` 的袭击成员不出这一行：trait 与武装是敌队的一部分，按该归一化会剥掉武装。「<nick>：敌对靶带生成随机」：敌对靶规格生成的靶按设计不归一化，行里列该靶未被禁的战斗技能、生成期 hediff、动物靶的未成年阶段。只在该靶参与被测交互时才是线索，远端靶的这一行不指向根因。「<nick>：kind <kind> 的异种是生成时掷出的 <异种>（未强制异种）」：键 `ROLLED-XENOTYPE`，随机掷出的基因进入被测量。「靶在用例期间站起」（无规格的靶）：跨百 tick 的靶要钉住，打伤制服的用 `SubdueAndPin`，生成期即定的传 `AwakeImmobile` 档，痛觉源用玩家阵营 pawn，预期内的死亡用 `ctx.ExcuseDeath` 声明。规格靶的站起与死亡行尾列规格：站起时要一直处于倒地的靶生成期传 `mobility=AwakeImmobile`，打伤制服的用 `SubdueAndPin`；死亡时要承受本用例的累计伤，假人提高 `healthScale`、别的物种换更耐打的物种；倒地顺带掷死时，改 `deathOnDowned=Off`。伤势在本 phase 内下滑的行：预期内的愈合用 `ctx.ExcuseHealing` 声明。「记伤害未关内传播」：比对伤量的伤害用 `RimRunnerDamage.Make` 构造。产品侧自定义的行由描述符登记 `LiveFingerprints` 产出，解读归产品根 |

## 引擎随包的检查与环境体检

缺省的回归批除了产品用例，还有引擎随包带的检查与环境体检，状态与产品用例一样参与结论。随包检查是回归用例；按 Id 指定批时，批里只含指定的那几条。环境体检按本批有无 World 级用例并入：

- **扫产品代码的随包检查**：SCOPE1、ILS1、CALL1、PGEN2、HANDLE1。SCOPE1 的违例落 FAIL，断言说明写明违例位置，按正文改产品。HANDLE1 的违例落 FAIL：产品的静态只读反射句柄按名未取到成员，或类上声明 `[HarmonyPatch]` 的类未挂上，多见于游戏更新之后；设计上允许为空的句柄、设计上不安装的补丁类在产品描述符里登记（`rimrunner-authoring` 的 `contract.md`「按名绑定的成员」）。HANDLE2 是引擎自己的同类检查，落 FAIL 时修正归引擎。ILS1 的读取失败是警告 `ILSCAN-UNREAD`，CALL1 的禁调违例是警告 `FORBIDDEN-CALLEE`，PGEN2 的直接生成违例是警告 `DIRECT-GENERATION`，正文在报告 `warnings`。ILS1 或 CALL1 落 FAIL 时，是扫描面或哨兵自检未成立，先查探针程序集、哨兵与对照
- **随包回归检查**：LOGCAP1、CFG1、WINSIZE1 这类不挂 `[RimRunnerEnvCheck]` 的检查，按普通回归用例进批。`--env-checks` 不选它们；指定另一份名单复核引擎承诺时，按 Id 指定 `run LOGCAP1`。LOGCAP1 失败时，本批「没有未认领错误级日志」不可信，无降档；指定另一份名单执行 `run LOGCAP1`，通过即表明两份名单的差集里有改写日志管线的 mod
- **环境体检**量引擎的承诺在本名单下是否成立：AGP1、ISOMAP2、AGEINJ1、DAY1、STQ1。
  失败断言的说明写该承诺与该承诺不成立的后果。这些承诺只有 RimRunner 的提供方能修。产品侧能做的是指定另一份名单，分辨是哪个 mod，
  或按下表降档

环境体检失败时的定档规则：降档只对断言失败生效。环境体检抛异常、带错误级日志、哨兵故障或收尾错误时仍判失败，按故障正文查：

| 环境体检 | 失败时 | 降档 |
| --- | --- | --- |
| AGP1、ISOMAP2、AGEINJ1 | 本批有用例用到对应设施（被钉住的 pawn、独立小图、经引擎生成的 pawn）时失败。说明的下一行点名这些用例：这些用例自身的状态不变，结论建在已损坏的设施上 | 无用例用到时自动降为警告 `ENV-CHECK-UNUSED` |
| DAY1、STQ1 | 失败。每条用例都在天光与叙事者之下，引擎无法判断哪些用例受影响 | 确认本名单的用例不受影响时，在名单里写 `[rimrunner].known_failing`（写法见 `modlists.md`），降为 `ENV-CHECK-KNOWN-FAILING`。该体检转为通过后许可零命中，进 RimRunner 日志 `[许可未命中]` |

指定另一份名单，要先确认引擎的承诺仍成立：环境体检执行 `rimrunner run --env-checks --modlist <名单>`，LOGCAP1 按 Id 指定 `rimrunner run LOGCAP1 --modlist <名单>`。`--env-checks` 是替换回归批而不是并入，只执行环境体检，不选 LOGCAP1 这类随包回归检查（见 `run --help`）。

`ENV-CHECK-INCONCLUSIVE` 来自 AGP1、AGEINJ1、LOGCAP1 的对照段：本名单下未钉的 pawn 未能开战、未能崩溃或未能长出老年病（引擎的生成入口一次都没走到老年病生成），或日志触顶后 `Debug.*` 仍可见（游戏不再在触顶时关日志）。未能开战、未能崩溃、未能长出老年病这三种情形，先查名单里是否有 mod 关闭或跳过开战、精神崩溃或老年病生成。
钉住、跳过与复位的那几段在本名单下无判定，设施本身仍成立。
`ENV-CHECK-UNUSED` 与 `ENV-CHECK-KNOWN-FAILING` 挂在引擎的环境体检上；`ENV-CHECK-INCONCLUSIVE` 中 LOGCAP1 这一份随 LOGCAP1 这条随包回归检查输出。`[RimRunnerAcknowledge]` 认领不到它们，也不必认领

## 五态裁决

各支写的是这个结论意味着什么、查哪里。被测侧何时改、何时停下来问，由产品仓自己的规程定。

**FAIL** → 分支：

- FAIL 行末带「（本条上次通过之后基线档已更换）」：通过率台账里本条上次通过之后有换档标。引擎按基线档内容指纹插入该标，`history` 条带与 `[偶发诊断]` 条带上是 `¦`。
  先按 `saves.md`「建完之后必做」分清该失败是否由换档引起。FAIL 再附「本条在基线档主图上执行」时，用例的地图即基线档里那张，换档最直接改到这张地图。
  是期望拟合旧档还是被测侧回归，按下面期望错、测试口径错、真回归三支各自的判据定
- FAIL 或 UNCLAIMED_FAULT 行下附「其它台账：<账本文件> <条带>」：本账里这条只有本轮一格。这条在同目录其余名单的台账里执行过。
  先比对两份名单的差异
- **期望错**（公式或出处过时）→ 改期望 JSON → `run <Id>`
- **测试口径错**（时序 / 随机性 / 清理不净）→ 先对照产品根自己记下的口径判据，再修用例 C# → 冷启动
  - 其中：**多阶段用例在批的组成改变之后转为 FAIL**（有用例并进或移出同一屏障批，或批序变），被测侧这一轮未改。
    指纹是该条目 `failureFingerprints` 里那行「本 phase 起于 tick …，比上一 phase 终点（tick …）晚 N tick」，N 比以往大，而失败在被测量的断言上；
    同批有哪些用例，看报告 `checkpointBatches`。落到 FAIL 的是声明预算、N 又未超该预算的条目。超出预算时，引擎自动让本条独占一批重新执行。未声明预算的批内失败也独占重新执行，通过即落 SENTINEL。
    小图成员另有指纹行「本图在两 phase 之间冻结，只走取回补推的 1 拍」。N 是时钟差，图上的在途状态未走，查的是按 `TicksGame` 到期的量。
    先查被测对象上有无随时间走、而用例未钉住的过程（愈合、休眠销毁、衰减、到期、自动控制器的节拍），算该过程在 N tick 内是否越线——
    越线即用例未钉状态或预算写宽，修用例（钉住，或把预算收窄到该值之下），被测侧保持不动；
    断言的上下界本身未算进外来 tick 的取整（按结算间隔整段入账的量）也落这一形
- **真回归**（`source` 公式仍对、实现已改变）→ 修被测侧，期望保持不动

**INCOMPLETE**（读数用例未完成）→ 看条目下的原因。`零产出` 是产出路径未走到或漏交，修用例。`截图没拍成` 是要的面板或按钮栏拍时未画出，或对象已不在图上，按报错改取景或现场。
`<Id>-Fail: …` 是用例自己认领测量未做成，先查理由里点名的对象，确定测量的前提是否成立，再按理由处理。

**UNCLAIMED_FAULT**（无主故障）→ 看条目下的 `errorSummary` 与报告 `newErrors`。被测侧报的错按真回归处理。用例有意制造的错误级日志改由 `AssertLogsError` 或日志许可认领。

**SENTINEL_FAULT**（哨兵）→ 看 `[哨兵]` 行与报告 `sentinelFaults`。该状态是用例经 `RimRunnerFault.Require` 认领的前提不成立，修夹具或前提，不进台账。

**NO_ASSERTIONS**（零断言）当轮单列一行，返回退出码 1，台账里不计通过（`history <Id>` 条带上的 `n`）。

## 复用轮与冷启动轮

并行实例上的 FAIL 与串行同等裁决。
重新执行一律 `run <Id>`，复用还是冷启动由 CLI 判。复用轮（`[复用]` 行）的失败与冷启动轮的失败同等裁决。复用轮执行在已执行过批的进程上，回载基线档复位世界，进程内的静态状态保持不动。要看一条失败是否随进程历史变：`rimrunner stop` 后再 `run <Id>`（冷启动），与复用轮对照
